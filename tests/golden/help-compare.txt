usage: atl-doctor compare [--scenario FILE] [--atl-dir DIR]
                          [--android-dir DIR] [--density D] [-o DIR]
                          [--prefix DIR] [--launcher CMD] [--atl-src DIR]
                          [--deep] [--no-aosp-fetch] [-h] [-q] [-v]
                          APK [ATL-ARGS ...]

Record the same scenario under ATL and on an Android device and write a short
report of the differences (OUT/report.md, OUT/report.json).

Arguments:
  APK                the app to record
  ATL-ARGS           arguments for android-translation-layer, after --

Input:
  --scenario FILE    step file for both sides (default: wait 15 s, then one
                     screenshot "start")
  --atl-dir DIR      compare this ATL capture instead of recording
  --android-dir DIR  compare this Android capture instead of recording
  --density D        Android screen density (default: from the capture)

Output:
  -o, --output DIR   output directory (default: ./atl-doctor-compare-<time>)

ATL environment:
  --prefix DIR       ATL installation prefix (default: $ATL_DOCTOR_PREFIX)
  --launcher CMD     start ATL with CMD instead of a prefix (e.g. a Flatpak),
                     as for record
  --atl-src DIR      ATL source tree for the stub list (default:
                     $ATL_DOCTOR_ATL_SRC)

Advanced:
  --deep             full method trace and agent from the start (debuggable
                     app: interpreter, timing changes)
  --no-aosp-fetch    do not download AOSP source (see report)

General:
  -h, --help         show this help and exit
  -q, --quiet        only errors on stderr
  -v, --verbose      more messages on stderr
